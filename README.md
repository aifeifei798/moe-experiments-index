## 四、ABS 门控方向（幅值 / 频域信号）

这条路不堆专家，而是研究**门控信号本身从哪来**：判据能不能建在幅值域和频域能量上（`|x|` 超阈值才放行、DCT 频段能量决定留多少），而不是只靠可学习的 softmax 路由。MoE 的门控打分最终用哪种判据，要从这条线出。

**它是怎么来的（别重走）**：起点是「用 JPEG/DCT 压 MoE 的 LoRA 权重」→ 实测不如 q4 系列，放弃 → 顺手偏到 KV 缓存压缩 → 也不理想（涨 ppl、解码慢 170×）→ 最后把同一套频域/幅值处理落到**门控信号**上，反而提了模型质量。同一个技术三次尝试，只有第三个目标成立。

| 仓库 | 起点 | 这个块自己在试什么 | 关键结果 | 状态 |
| :--- | :--- | :--- | :--- | :--- |
| [Harmonic-LLM](https://github.com/aifeifei798/Harmonic-LLM) | gemma-4-12B 的 `q_proj` / `o_proj` | 一个 forward hook 做软拐点限幅：按块峰值 / 中位 RMS 判幅值离群，只压超过 ceiling 的元素，权重和 calibration 都不动（已发 PyPI） | **已整合进 Transformers：接入就是给一个高阈值（默认 64，取在 p99.9 之上），不训 LoRA、不改权重、不需要校准数据**。离群重尾但极稀：p99 为 17.9 / 35.1（Q/O），max 95.6 / 286.5；默认档只碰 **0.001%（Q）/ 0.07%（O）** 的块，峰值中位降 **−21.2% / −15.8%**；代价 NLL 0.173→0.293、吞吐 21.0→15.0 t/s（0.71×）；**sham 对照推翻原设想——起作用的是 ceiling 不是块选择**（随机块 KL 0.0015 vs 门控 0.092） | ✅ 已实现并集成（配置即用） |
| [flashcodec-kv](https://github.com/aifeifei798/flashcodec-kv) | transformers 5.x `Cache` | 把 `(B,H,S,D)` 的 seq 轴当图像：JPEG 式分块 DCT 只留最低频 K 个系数 + int8；PNG 式锚点 + 一阶差分走无损；验证「频域能量集中」能不能直接换成显存 | `k=2` + int8 压到原始 KV 的 **6.6%（15×）**、PSNR 46.9 dB；一阶差分方差塌 **30×**；安全默认 `keep_freqs=8` + int8 ≈ **52% 体积 / 稠密模型 +2% ppl**；无损档位逐位一致但只省 ~1.9×（存储）；per-token 解码在 S=4096 慢 ~170× | ✅ 已验证（含负结果：k=2 稠密模型崩） |

### 溢出：同一套判据搬到扩散采样

判据抽象出来之后就不再属于 MoE，这是它第一次跨域验证有效的记录。

| 来源 | 落点 | 结果 |
| :--- | :--- | :--- |
| ABS 门控（幅值判据 + tanh 软拐点，Harmonic-LLM 原型） | [ComfyUI-FeiFei](https://github.com/aifeifei798/ComfyUI-FeiFei) → `harmonic_eq_node.py` | **有效**。作为 MODEL patch 装在 CFG 合成预测上：高拐点限幅治高 CFG 的过曝 / 死黑 / 蜡感，低拐点（AGC）提暗部；健康区逐位不变，权重复原 bit-exact；SD1.5 / SDXL / Flux / 任意 DiT 通用（走 CFG 槽而非 attn2 patch） |

> 同一条 `q_proj` / `o_proj` 上还挂着另一支进行中的实验：**把专家直接做成 Q/O 的 LoRA**，而不只是在这里判幅值（见第一节最后一行）。两支共用同一组投影，结论互相参考。

### 最终落点：压门控，不压权重

同一套频域/幅值处理，压权重失败、压 KV 一般，落到**门控信号**上反而把模型质量提上去了（具体指标待补）。这条比上面的数字更值得记：技术本身没错，错的是被压的对象——权重是稠密且已经是低秩的，KV 是尺度敏感且要解码速度的，门控信号才是那个既稀疏又存在大量无效幅值的对象。

### 研究假设：Q/O 曲线决定上限（🟡 当前研究方向）

**假设**：模型 `q_proj` / `o_proj` 的幅值分布与频谱形态（"曲线"）对能力有决定性影响；不训练、只做曲线整形（限幅 / 软拐点 / EQ），就能让模型比出厂状态更好。类比音频的整型压缩与 EQ——物理上回不到无损，但听感确实更好；模型同理，到不了大模型，但比出厂强。

**机制猜测**（两条都与"曲线"直接相关，不是比喻）：

- **局部温度**：EQ 是对 `q/o` 的逐块增益 ≈ 给每层一个可变的注意力温度。离群块降温 → softmax 从近 one-hot 拉回来 → 注意力不再塌在少数 token 上 → 长上下文和指令跟随更稳。
- **有效秩**：幅值尾部决定参与计算的方向数。压平尾部 ≈ 更多方向被用上，同样的参数用得更满。

**已有的支撑**：幅值尾部极重（Q p99 17.9 / max 95.6，O p99 35.1 / max 286.5）；整形后任务表现变好；**同一模型 NLL 反而变差（0.173 → 0.293）**。

**必须先定义"好曲线"**——这是这个假设能不能成立的关键，两个方向都有机制支持，搞反就变成不可反驳的叙事：

| 方向 | 支持 | 如果成立意味着 |
| :--- | :--- | :--- |
| A. 越平滑越好 | 离群扭曲注意力、量化更难 | 强模型的尾部应更轻 |
| B. 越有结构越好 | massive activations 是功能性的（attention sink、检索锚点） | 强模型的尾部应更重但更整齐 |

**最小实验（都很便宜）**

1. **跨模型测量**：`ratio` 分布的 p99 / p99.9、每层 attention 熵、Q/O 奇异值谱（有效秩），与 benchmark 分数做相关——先看 A 和 B 谁对。
2. **本模型 Pareto**：`threshold × alpha_max` 扫描，横轴任务分、纵轴 NLL。单点说明不了"更好"，曲线才能说明在哪里用似然换任务表现。
3. **Sham 消融**：同范数随机增益，排除"加噪声 / 正则"效应（Harmonic-LLM 已经证明这招能翻盘）。

**两个反例风险**

- **可能只是去量化噪声**：若收益只在 QAT / 低比特模型上出现，那它是在补量化损伤，不是普适规律——必须在全精度底座上重跑一次。
- **窄任务提升 + 泛化退化**：NLL 变差意味着模型被推离原分布，要专门盯复读、指令跟随退化，别只看喜欢的那几个 prompt。

**报告口径**：这是"感知/任务层面的收益，似然层面的代价"，和 mp3 对无损的关系一样。用 NLL 证明它对是错的，用 NLL 否定它也是错的。

### 边界怎么找（调参协议）

现在的状态是"思路成立、实现完成、不知道调多少"——这不是工程问题，是**没有目标函数和停机条件**。边界可以定义成一句话：**任务分不再涨、护栏开始掉**的那个点。所以要先有三层指标，再谈搜索。

| 层 | 指标 | 判什么 |
| :--- | :--- | :--- |
| **硬指标** | 数学 exact match、代码单测通过率、检索固定串命中 | 判"智商"，不受文风影响 |
| **软指标** | 40 条固定 prompt 与 base 的盲评 A/B（同 seed、控制长度） | 判"听感"，对应 EQ |
| **护栏** | 复读率、指令格式合规率、长度膨胀、attention 熵下限、NLL 偏移上限 | 找悬崖在哪 |

**搜索流程**

1. **粗扫 12 组**：`threshold ∈ {16, 32, 64}` × `alpha_max ∈ {0.25, 0.5, 1.0}` × 层带 `{early, mid, late}`，只取一个层带先跑。
2. **收窄**：取前三，`alpha_max` 按 0.1 步进精扫。
3. **逐层**：离群集中在中层，只在中段打开，前 1/4 与后 1/4 关掉做对照。
4. **只比基线**：每组都跟「永远 base」比，不看绝对值。
5. **一次一张表**：参数 / 硬分 / 软分 / 护栏四点记下来，边界会自己浮出来。

**音频 mastering 的正确类比**：不是"凭耳朵调"，而是 reference track + metering + 0.5 dB 小步进 + 等响 A/B。对应过来——冻结 base 输出当 reference，`duty` / `ratio` / attention 熵当 metering，`alpha_max` 小步进，比之前先对齐生成长度和温度。

**还不知道的细节（按影响排序）**

- 层带位置：离群集中在中层是已知的，但边界在 12–24 还是 18–30 还没量过。
- `per-block` 增益 vs `per-channel` 增益：后者更外科、更可能拿到真收益，但需要校准。
- 只压正尾还是双边都压。
- 全精度底座 vs 量化底座：决定这是普适规律还是去量化损伤。
- 与 system prompt / chat 模板的交互：收益可能部分来自"对模板更鲁棒"。

**最容易骗自己的坑**：LLM 评委偏爱长回复、偏爱格式整齐。硬指标必须能判对错，否则"嘎嘎好"可能只是"更好看的废话"。

### 这个假设的边界（先划好，免得过度承诺）

母带能改的是**分配**，不是**内容**：它调不出模型没见过的东西。所以成立范围可以先预期成：

| 大概率有效 | 大概率无效 |
| :--- | :--- |
| 风格 / 语感 / 格式 | 新知识、新语言 |
| 长上下文稳定性 | 新的数学、代码技能 |
| 量化损伤修复 | 稀缺事实回忆 |
| 指令跟随鲁棒性 | 需要新特征组合的推理 |

这条边界顺便解释了前面那组观察：**为什么 Q/O 整形对风格有用，而理科补充必须单独训练**——整形改分配，训练改内容。两件事是同一条规律的两面。

## 五、当前架构：三层解耦（设计记录）

这里不记结果，记结构。目的是换分类、换子模型、换底座时照着检查一遍，不用重新推。

三段，可单独训练，坏一块不会污染另外两块：

1. **理科补充核** —— 单独训练，一个大 LoRA 挂在冻结的原模型上（不克隆 MLP），构成第二大核；比 DualBigLittle 的克隆核省一整份权重显存。
2. **分类 + 分类子模型** —— 小核负责规划分类与分类组合。
3. **决策模型** —— 吃规划结果，输出「每层用多少专家、用哪些、在哪几层」的分配表，替代 per-layer MoE 路由。

锁序：**理科核 → 子模型 → 决策**。任何一块单独重训都不该动另外两块。

### 三条接口契约（不写清就会变成隐性耦合）

| # | 契约 | 怎么防 |
| :--- | :--- | :--- |
| 1 | **子模型按「可组合」训，不按固定槽位训** | 训练时随机化层区间 / 专家数 / rank。否则决策一改表，子模型就落到训练时没见过的槽位，表现为「决策学坏了」，其实是分布外 |
| 2 | **决策永远滞后于子模型** | 每次决策训练记录 `submodel_set: vN`；子模型重训后跑固定探针集（~200 条）比决策命中率，掉超阈值就重训决策，别等终指标 |
| 3 | **分配表要有语法** | 层区间取 `{early, mid, late}`、专家数取 `{2, 4, 8}`、专家限定在固定簇内。动作空间小才可能在小数据上泛化；同时记计划分布，若 >90% 样本出同一张表，说明「动态」是假的 |

### 两条工程约束

- 原模型小 → 决策必须极小：每段或每请求一次，LoRA 大小的头，**不要每 token 一次**，那点开销在小模型上会吃掉收益。
- 分配表 = 每层容量调度，初始先验直接取稀疏档（2~4 专家）：依据是 Mini-Architecture 的「top-8 用 1/12 可见 token 拿到 90% 质量」。

### 验证时先打这三个基线

决策的增益必须打赢**最好的常数计划**：永远 base / 永远理科核 / 永远最强单核。打不赢就说明动态决策只是在做平均。

## 七、可以当事实用的结论（跨仓沉淀）

1. **专家住主机 RAM 不损吞吐**：每层搬运 ~0.13 ms，被 ~40 ms 的 forward 完全掩盖；host 24.9 vs device 23.8 t/s。
2. **Top-K 的 K 是成本不是收益**：Top-1 36.5 > Top-8 22.4 t/s，路由开销随 K 线性增长。Top-8 的用途是验证协同路由，不是提速。
3. **辅助损失必须逐层平均**：被 `/num_layers` 稀释 28 倍后，路由命中率 34~46%（等同随机猜），修复后 82~98%。看 loss 曲线看不出来，要看命中率。
4. **路由修好会牺牲文科保真**：Arts PPL 5.49 → 8.20。这是架构取舍，不是 bug；要同时保住两头得另找约束。
5. **稠密前向 + 软门控能让全部专家吃到梯度**：896/896 非零、0/28 层饿死，靠 `test_every_expert_receives_gradient` 锁住。
6. **权重差分不量化就不省体积**：bf16 差分仍是 504 MiB（Δ 只占 0.11%~0.21% 但不稀疏）；int8 差分 −45%，PPL 变化在小数第 4 位。
7. **单卡训 25,200 专家是可行的**：低秩张量收缩省 97.6% 训练显存 → 10 GB、9.8 samples/s。
8. **因果 LM 错位不报错但致命**：loss 17~19，而 `ln(262144)=12.5`，比随机初始化还差。必须有断言，否则训练照跑。
9. **251K 词表必须 chunk logits**：`B=4, T=256` 一份 bf16 logits 就 0.5 GiB，`.float()` 再翻倍。
10. **能烘回 stock 架构**：dense 版余弦 0.9935、MoE 版 5.62B 余弦 0.9988，可以不依赖 `trust_remote_code` 交付。
11. **幅值离群是重尾但极稀，阈值必须放高**：Q/O 的 p99 已经到 17.9 / 35.1，阈值落进 2–8 就是在切模型正在用的激活；安全点在 p99.9 之上（默认 64）。
12. **门控的收益可能来自 ceiling 而不是「选得准」**：随机块 sham 的 KL 比真门控低 60×（0.0015 vs 0.092）。ABS 门控上线前必须先跑这个对照，否则会把「限幅降损」记成「路由有效」。
13. **频域压缩的崩塌点在低码率**：KV 上 `keep_freqs=2` 在稠密模型直接崩，`keep_freqs=8 + int8` 才是安全点（52% 体积 / +2% ppl）。
14. **幅值判据是通用算子，不是 MoE 专用**：同一套「robust 参考电平 + tanh 软拐点」原样搬到扩散模型的 CFG 合成预测上（`harmonic_eq_node.py`）就治住了高 CFG 过曝——说明当初抽象出的是判据，不是路由代码。
15. **零训练就能接入**：Harmonic-LLM 已经整合进 Transformers，接入只是给一个高于 p99.9 的阈值（默认 64），不训 LoRA、不改权重、不需要校准数据；运维判据是 **duty > 0.1% 就说明阈值切进了工作区**，此时调 `alpha_max` 而不是继续抬阈值。
16. **换对象比换技术更值**：同一套 DCT / 幅值处理，压 LoRA 权重不如 q4、压 KV 只是勉强、压门控信号反而提质——技术选型的第一步是先选对被压的对象（稀疏、且含大量无效幅值的那一个）。

## 八、评测口径（这些数字不能混用）

- **采样方式**：域内分层等距 vs 取前 n 条，同一权重 Arts PPL 分别是 5.49 与 12.46。
- **数据切分**：验证集 vs 训练语料切片，绝对值不可比，只能看相对差。
- **吞吐**：必须按实际生成 token 计；旧版用固定 `45/elapsed` 把 Top-8 算快了，也把 Top-8 说成了优于 Top-1。
- **去重**：三种口径分开报——题面唯一率 / 答案唯一率 / `(prompt, response)` 字节唯一率。字节去重会让换皮题吃满配额。
- **路由指标**：先按层平均再报；`97.06 / 35 ≈ ln(32)` 是正常值，不是爆炸。
- **旧 README 的乐观数字**：`Code −55% / Math −51% / Arts −40%` 是 in-distribution 结果，不要引用，用 DualBigLittle 的 −9.5%。

## 九、还没定的事（整合前要回答）

- **哪些方向要合、哪些保持独立**：25K 的簇拓扑、8×16×256 语义分类学、TriTier 的三档适配器、DualBig-2B 的「双核 + 1,120 专家」，目前是四套互不兼容的骨架，不是同一个东西的四个版本。
- **评测坐标系**：各块口径不同（分层等距 / 取前 n 条 / 训练切片 / 验证集），整合前得先统一到一套，否则没法判断哪个方向值得带进最终版。
- **μP 维度自适应缩放**能否跨底座迁移（0.6B → 8B / 12B），还是每个底座都要重标定。
- **交付形态**：走 `bake_*` 烘成 stock 权重，还是保留 host 流式层 + 自定义 modeling。
- **后端归属**：25K 的推理服务目前不在仓里，整合时要不要收进来。
- **ABS 门控接在哪一层**：只压 `q/o` 的离群幅值，还是直接当专家选择的判据（`|x|` 超阈值才放行某组专家）。
- **幅值判据 vs 频域判据**：`|x|`（Harmonic-LLM）和 DCT 能量（flashcodec-kv）现在一个用来限幅、一个用来压缩，还没在路由信号上正面对照过。
- **Q/O LoRA 专家 vs FFN 微专家**：单 LoRA 已经能稳定承载一个域，接下来要回答的是多 LoRA 之间的相互干扰，以及两条路在显存、吞吐、路由可分性上的取舍。
- **门控压缩为什么能提质**：目前只知道有效，不知道为什么。候选解释——路由信号去噪（大幅值 token 不再抢路由）、等效于温度平滑、或者只是抑制了离群对门控的干扰。机制不清楚就没法判断能不能推到别的模型和别的层。
- **"好曲线"是平滑还是有结构**：见第四节「研究假设：Q/O 曲线」。先跨模型量出方向，再谈能不能做成可复用的整形配方。
